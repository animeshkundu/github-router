# Unsupported features (Copilot can't serve)

Anthropic API surfaces with no Copilot equivalent, and how the proxy degrades:
explicit Anthropic-format errors, server-side wiring (ADVISOR), or fail-fast 400s.
See [`../CLAUDE.md`](../CLAUDE.md) for project overview.

## Explicit limitations

- **Files API** (`/v1/files/*`): Copilot has no equivalent storage backend (verified via `cc-backup/src/services/api/filesApi.ts`). The proxy returns 404 with a descriptive error pointing users at the real Anthropic API for file uploads/downloads.

- **ADVISOR** (`advisor-tool-2026-03-01`): Copilot returns 400 "unsupported beta header" on this prefix. **Phase I (shipped, auto-enabled for `github-router claude`)**: the proxy injects a `__anthropic_advisor` tool into the body, intercepts the model's `tool_use` blocks for that tool name, runs an advisor model server-side (**lead-aware**: `gpt-5.6-sol` via `/v1/responses` for a cross-lab "second set of eyes" on an Opus lead, escalating to `claude-opus-5` via `/v1/messages` on a lighter Claude lead, which is the only transcript-aware path to the Anthropic frontier a budget session has. Effort follows the Claude Code picker rather than a constant, floored at `high` and clamped to the resolved advisor's own ladder; with no picker signal it stays at the historical `xhigh`. `GH_ROUTER_ADVISOR_MODEL` pins either model on any lead), and emits translated `server_tool_use{name:"advisor"}` + `advisor_tool_result` blocks back to the client on the same SSE connection. Advisor-only turns continue server-side through up to 16 calls. If the same executor turn also emits ordinary client tools, the proxy emits the advisor result and ends with `stop_reason:"tool_use"` instead: Claude Code must execute those tools before continuation. On the next request the proxy translates the advisor pair back to its internal tool call and merges the advisor result with all client `tool_result` blocks in one immediate user message. It never continues with an unresolved client tool, synthesizes a missing result, or rewrites a signed thinking block. One terminal `message_delta` covers the whole synthetic response, with accumulated usage. The `claude` subcommand sets `CLAUDE_CODE_ENABLE_EXPERIMENTAL_ADVISOR_TOOL=1` automatically (without it, Claude Code's `JI()` gate falls back to the `tengu_sage_compass2` GrowthBook flag, which is off for non-Anthropic users). Three opt-out paths, all honored: `CLAUDE_CODE_DISABLE_ADVISOR_TOOL=1` (documented Anthropic opt-out, checked first in `JI()`), `CLAUDE_CODE_ENABLE_EXPERIMENTAL_ADVISOR_TOOL=0` (proxy uses presence-based guard — any user-set value preserved), or `CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS=1` (global beta opt-out — proxy intentionally doesn't strip this from your shell). The advisor model is dispatched to `/v1/responses` with `reasoning.effort` for gpt-5.x / o-series / codex models, and to `/v1/messages` for claude-* models. The `/v1/messages` branch was unreachable until the Opus escalation existed, so it previously dropped the effort entirely and capped output at 4096; it now sends `thinking:{type:"adaptive"}` + `output_config.effort` (gated on the model advertising `adaptive_thinking`) and sizes `max_tokens` from `max_non_streaming_output_tokens`. Probes `advisor_claude_adaptive_thinking` / `advisor_claude_nonstreaming_cap` / `advisor_claude_streaming_cap_accepted` are the live evidence for that body shape. If a future Claude Code version stops emitting `advisor-tool-` despite our inject, check whether Anthropic rotated the env name. See `src/services/advisor/advisor.ts`. **Fast profile**: an authenticated `-m fast` primary lead uses fixed `gemini-3.8-flash` as the transcript-aware Advisor at high effort across every permitted `/model` selection (Luna, Sol, Grok, Gemini, or Opus). The launcher pins Claude Code's client setting to `gemini-3.8-flash[1m]`, while the proxy sends the bare id to Gemini's live Chat endpoint. Forwarded Advisor flags and `GH_ROUTER_ADVISOR_MODEL` cannot override fast mode; a missing endpoint invariant or conflicting in-session `/advisor` selection fails visibly instead of falling back. Standard pins remain authoritative. Non-Claude leads run through the caller-abortable streaming shim and continuation returns through that lead's same endpoint; Task subagents still degrade by stripping Advisor. User-facing guidance calls this role Advisor, not Gemini Advisor. See [`default-models.md`](default-models.md).

- **Broken signed-thinking history recovery**: some Claude Code history-rebuild paths persist/replay a latest assistant turn that Copilot rejects because its signed thinking was modified or has an invalid signature. Valid Opus 5 omitted-display thinking also has `thinking:""`, so the proxy does not guess from request shape. It forwards the original request first and uses a known upstream integrity 400 (`cannot be modified` or `Invalid signature in thinking block`) as the discriminator. It then removes only `thinking`/`redacted_thinking` blocks from the rejected `messages.N` assistant turn and retries, preserving every text/tool/result block and the top-level thinking configuration. Recovery is bounded by `MAX_THINKING_REPAIR_ATTEMPTS` (5 semantic repairs per request, so at most 6 upstream calls from that loop) and gives up immediately if upstream re-names an index already repaired, so a non-converging history cannot spin. Resolving `messages.N` tries the reported index **directly first**, which is the behavior every already-working request keeps; only if that fails does it try a hoist-adjusted index, for the case where a client placed a non-conversation role (`system`) inside `messages[]` and upstream dropped it before validating, shifting every later index. The adjusted candidate is accepted only when the content block upstream actually named is a signed thinking block at that position, so a wrong guess declines instead of stripping blocks from an innocent turn. A successful repair is memoized with a salted in-memory fingerprint so the same process can repair later replays before the upstream call. The proxy never edits Claude Code JSONL transcript files or stores message/signature content; a failed repair returns the original upstream 400.

- **`mcp_servers` body field** (inline remote-managed MCP): Copilot 400s on this field. Phase G's planned proxy-side translate-path was deferred (codex-critic: structural design holes — continuation-after-pool-TTL not implementable from request alone, streaming buffer-and-resume creates incoherent SSE if any assistant deltas already forwarded, tool-name namespace `server:tool` regex unverified against Copilot). The proxy now **fail-fast 400**s requests with non-empty `mcp_servers` and points users at local stdio MCP via `~/.claude/mcp.json` (which works without the translate path). Empty `mcp_servers: []` arrays pass through (Copilot 400s but not the proxy's concern).

- **Bridge / CCR (Remote Sessions)**: requires `CLAUDE_CODE_REMOTE`/`CLAUDE_BRIDGE_*` env vars. Stripped from the spawned-child env (`STRIPPED_PARENT_ENV_KEYS`) so the remote-session code path never activates. Local sessions only.

- **Files API OAuth, account/settings, team-memory sync, user-settings sync, etc.**: gated by `DISABLE_NON_ESSENTIAL_MODEL_CALLS=1` + `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1` + `DISABLE_TELEMETRY=1` (all set by `getClaudeCodeEnvVars`). Suppressed at the source.
