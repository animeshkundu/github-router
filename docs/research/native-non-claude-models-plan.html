2 · The two gates

Making a model “native” means passing both gates. They live at different layers.

Gate 1 — selectable in Claude Code (config-only, tiers retained). Claude Code’s picker is extensible. Two additive levers (neither overwrites opus/sonnet/haiku): ANTHROPIC_CUSTOM_MODEL_OPTION (adds a picker row) and/or CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY fetching the proxy’s /v1/models (but it filters to ids starting claude/anthropic, so a non-Claude id needs a claude-* alias). Exact env-var names are Claude-Code-version-dependent — verify against the installed build during Phase 3.
Gate 2 — the proxy actually serves the traffic (the real work). Today /v1/messages (create-messages.ts:73) forwards unconditionally to Copilot’s Anthropic endpoint, which serves Claude only; a selected gpt/gemini request 400s. We add a translation shim that fires only for non-Claude target models. That scoping is the non-regression guarantee.

3 · Architecture — unified-Chat-as-hub

Adopt @musistudio/llms’s proven design: one canonical intermediate (OpenAI Chat shape), an Anthropic ingress transformer on one side, a provider transformer on the other. This makes Gemini nearly free (Copilot serves it as chat-compat) and isolates the Responses complexity to a single provider transformer.

/v1/messages handler (branch at handler.ts:310, BEFORE createMessages) ├─ target is a Claude model → EXISTING passthrough (opus/sonnet/haiku: byte-for-byte unchanged) └─ target is non-Claude → TRANSLATION SHIM Anthropic Messages ↓ anthropicToUnified() [port: musistudio anthropic.transformer request map] Unified Chat request ↓ ├─ gpt-5.5 / gpt-5.3-codex → unifiedToResponses() [reuse OUR stream-fn.ts buildResponsesPayload] → Copilot /responses └─ gemini-* → unifiedToChat() → Copilot /chat/completions ↓ provider stream providerStream → unifiedChatEvents ↓ unifiedToAnthropicSSE() [port: musistudio anthropic.transformer.ts:256-950] Anthropic SSE → Claude Code

5 · Non-regression guarantee (opus / sonnet / haiku)

  • The shim is reached only by an explicit non-Claude branch keyed off the resolved model’s endpoint/family. The Claude path calls the same createMessages passthrough it does today — not one byte changes for opus/sonnet/haiku.
  • Gate-1 selection uses additive levers (ANTHROPIC_CUSTOM_MODEL_OPTION adds rows; gateway discovery only appends). Tier defaults (ANTHROPIC_DEFAULT_*) are untouched.
  • A regression guard test asserts a Claude-model request never enters the shim branch.

6 · Phasing (each phase independently testable)

Phase 0 — scaffolding & branch. Add the non-Claude branch point in handler.ts; a translateAnthropicToProvider module skeleton; endpoint/family classifier reusing endpoint.ts. Claude path untouched (guard test).
Phase 1 — OpenAI Responses path (gpt-5.5, then gpt-5.3-codex). Anthropic→unified request map; unified→Responses via reused buildResponsesPayload; port the Anthropic SSE synthesizer; wire Responses-decode→Anthropic-emit. Non-streaming + streaming. This is the bulk of the work.
Phase 2 — Gemini chat path (gemini-3.5-flash, gemini-3.1-pro-preview). Unified→chat passthrough + chat-SSE→Anthropic-SSE (largely the same synthesizer). Reasoning clamp + structured-output gap handling.
Phase 3 — selection/registration. Inject ANTHROPIC_CUSTOM_MODEL_OPTION (verify env-var name against installed Claude Code); optionally normalize /v1/models for gateway discovery under claude-* aliases. Non-regression on tiers.
Phase 4 — verification, probes, docs. Compat-matrix rows + probes per model/endpoint; live smoke per model; the streaming race tests below; update CLAUDE.md + design docs.

7 · Testing & verification strategy

  • Mapping unit tests both directions: Anthropic→Responses/chat request (text, image, tool_use, tool_result, tool_choice, thinking, stop_sequences) and provider→Anthropic response (content blocks, tool_use, usage, stop_reason).
  • Streaming SSE synthesis tests: assert the exact Anthropic event sequence (message_start → content_block_start/delta/stop for text + input_json + thinking → message_delta w/ stop_reason+usage → message_stop), multi-tool id correlation, mid-stream tool-call arguments.
  • Stream-lifecycle race tests (repo mandate): this is a new synthesized-SSE surface (not a passthrough relay), so every enqueue/close must have an enqueue-after-cancel race test per the review checklist. The ported musistudio guard helps, but we must add the tests.
  • Probes + compat matrix: an end-to-end 200 probe per model on its real endpoint; matrix rows with accept/reject expectations.
  • Live smoke per model through Claude Code: text, tool use, thinking, long-context.
  • Gap assertions: gemini xhigh→high clamp; gemini structured-output degradation surfaced, not silent.

8 · Risks

  • Streaming correctness is the hard part. Synthesizing Anthropic SSE with correct tool-call/block-index correlation and stop-reason overrides is fiddly; mitigated by porting a battle-tested synthesizer + LiteLLM’s mapping as the spec + our superior Responses decode.
  • New stream-lifecycle surface → the repo’s enqueue-after-cancel race class applies; addressed by explicit race tests, not just the inherited guard.
  • Claude Code selection env-var drift (version-dependent) → verify against the installed build in Phase 3; fall back to -m/ANTHROPIC_MODEL if the custom-option name differs.
  • Capability accounting (context window, effort) assumes the current model unless overridden → register accurate windows via the custom-model-option.
  • Surface size (~1.2–1.8k LOC + tests) → phased, each phase shippable and independently tested.
