# OPERATING_DEFAULTS_DIRECTIVE

## Identity

- **What**: The highest-salience behavioral default injected into the spawned agent. Two principles: (1) **Orchestrate**, delegate heavy / parallel / context-heavy work to the right subagent, worker, or model, keeping the main context free, while still doing trivial and last-mile work directly; (2) **Aim high**, an excellence lens stated as a principle, with the well-known names (Jobs and Ive / Gates / Bezos) appended only as a "bar to clear" calibration, guarded by an explicit no-impersonation / no-theatrics rule.
- **Constant**: `OPERATING_DEFAULTS_DIRECTIVE`, `src/lib/claude-md-injection.ts:101-117`. Design rationale comment at `:80-100`.
- **Injected via TWO surfaces (double exposure to the main agent)**:
  1. `--append-system-prompt`, `src/claude.ts:1084-1088`. It LEADS the single system-prompt arg (`${OPERATING_DEFAULTS_DIRECTIVE}\n\n${peerAwarenessSnippet}` when the peer snippet exists, else the directive alone). This push sits OUTSIDE the codex-mcp `if` block (which closes at `claude.ts:1072`), so it fires unconditionally, even under `--no-codex-mcp` (comment at `claude.ts:1074-1076`).
  2. Mirrored CLAUDE.md TOP, prepended by `prependOperatingDefaultsToMirroredClaudeMd` (`claude-md-injection.ts:694-704`), called from `src/claude.ts:1091`. This reaches descendants (Agent-tool subagents, agent-teams teammates).
- **Surfaces**: system prompt (main agent, highest attention weight) AND mirrored CLAUDE.md top (descendants). The main agent therefore sees it TWICE.
- **Gate**: none on the system-prompt push (always). The CLAUDE.md prepend is best-effort. Size: 1137 bytes.
- **Position in final CLAUDE.md order**: topmost (last prepend to run wins the top slot).

## Text (verbatim)

`src/lib/claude-md-injection.ts:101-117`:

```
## Operating defaults (apply when the user has not specified otherwise; the user's explicit direction and the domain's own standards always override)

Orchestrate. Delegate research, implementation, review, and large reads to the right subagent, worker, or model (worker-* agents for background non-blocking runs, Task subagents for parallel work, peer critics for review) so your own context stays free to reason and collaborate with the user. Prefer parallel delegation for independent work. Do trivial, surgical, and last-mile work directly; delegate the rest rather than doing it yourself and filling your own context.

Aim high. Default to radical simplicity and relentless focus on the user's real experience (the Jobs and Ive bar for design), whole-systems first-principles thinking that anticipates scale and the long arc (the Gates bar for architecture and tech), and customer obsession that works backwards from the outcome (the Bezos bar for product and business). Question every assumption and prefer what you can derive, reproduce, or test. Adopt the principles, not a persona: no impersonation, name-dropping, or theatrics.
```

## Anthropic-guideline assessment

- **Role framing (the key call)**: Anthropic's role guidance is functional, "Setting a role in the system prompt focuses Claude's behavior and tone for your use case. Even a single sentence makes a difference", with the worked example a functional specialization ("You are a helpful coding assistant specializing in Python"), not a named persona ([Prompting best practices, "Give Claude a role"](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-4-best-practices)). The overarching lever is specificity: "Being specific about your desired output can help enhance results ... The more precisely you explain what you want, the better the result" (ibid., "Be clear and direct"). There is no official page that explicitly speaks to named-celebrity / "be as good as <famous expert>" framing, so the assessment below rests on the general specificity principle, not an explicit anti-celebrity statement. Under that principle, a concrete functional description of the desired behavior is the reliable control signal; a named entity is a denser, higher-variance vector that risks pulling persona noise in at high salience. The current text HYBRIDIZES: the principle leads in plain functional language ("radical simplicity and relentless focus on the user's real experience", "whole-systems first-principles thinking that anticipates scale", "customer obsession that works backwards from the outcome"), and the name follows only as a calibration bar in parentheses, with an explicit `Adopt the principles, not a persona: no impersonation, name-dropping, or theatrics` guardrail. This is the mitigated form of the pattern: the stated principle does the steering; the name is a secondary anchor. It is stronger than a bare "be like Steve Jobs" role, and by the specificity principle the fully-specified behavior would carry the signal with the name dropped entirely.
- **Positive / prohibitive**: Positive throughout the two principles ("Orchestrate", "Delegate...", "Aim high", "Question every assumption"). The only prohibition is the guardrail ("no impersonation, name-dropping, or theatrics"), which is the correct place for a negative, it fences off the specific failure mode the named-persona framing invites. Well-shaped.
- **Overtrigger risk**: Low-to-moderate. No MUST/ALWAYS/CRITICAL/all-caps, which matters because Anthropic explicitly warns that Opus 4.5/4.6 "are also more responsive to the system prompt than previous models ... these models may now overtrigger. The fix is to dial back any aggressive language. Where you might have said 'CRITICAL: You MUST use this tool when...', you can use more normal prompting like 'Use this tool when...'" ([Prompting best practices, "Tool usage"](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-4-best-practices)). This block already writes in that "more normal" register. "Orchestrate." and "Aim high." are terse imperatives, but they are directional defaults, not forceful absolutes, and the header explicitly makes them overridable ("apply when the user has not specified otherwise; the user's explicit direction and the domain's own standards always override"). The overridability clause is the main defense against the orchestrate default overtriggering into "delegate everything, including the one-line fix", reinforced by the explicit `Do trivial, surgical, and last-mile work directly` carve-out. Anthropic's own subagent-overuse note is the exact hazard this carve-out addresses: Opus "may spawn [subagents] in situations where a simpler, direct approach would suffice ... for code exploration when a direct grep call is faster" (ibid., "Subagent orchestration").
- **Literalness / scope**: Good. Opus 4.8 follows instructions precisely and benefits from explicit direction, "Claude's latest models are trained for precise instruction following" ([Prompting best practices, "Tool usage"](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-4-best-practices)), and adding the reasoning behind an instruction helps ("Providing context or motivation behind your instructions ... can help Claude better understand your goals ... Claude is smart enough to generalize from the explanation", ibid., "Add context to improve performance"). So the two things that matter are stated explicitly: (a) the override boundary (header), and (b) the do-it-directly carve-out. Without the carve-out, a precise-following model could read "delegate the rest" as "never touch anything myself." The carve-out closes that. The excellence lens is scoped per-domain (design / architecture / product), which helps the model apply the right bar to the right work rather than blanket-applying one.
- **Enforcement claims**: None. It is a "default", explicitly overridable, the honest framing for injected context that no hook enforces. It does not claim the orchestrate posture is mandatory or validated.
- **Structure**: Markdown `##` header + two labeled paragraphs. Clean and scannable. The header doubles as the scope/override statement, which is efficient.

## Don't-nerf / right-balance

- **Orchestrate default, right thing, right amount?** Yes, with the carve-out. The proxy ships a large delegation surface (workers, subagents, peer critics, orchestrate tools); without a default posture the model under-uses them. Stating "delegate the heavy/parallel/context-heavy work, do the last-mile directly" raises the floor (the surface gets used) without nerfing (the model still does surgical work itself, and the user can override). The explicit carve-out is what prevents the over-delegation nerf where a model relays a trivial edit through a worker and loses fidelity + adds latency.
- **Excellence lens, worth the named-persona risk?** This is the contested call. The upside: the principle-led form gives the model a concrete quality bar per domain. The risk: even mitigated, the names sit at the highest-salience position (system prompt, leading the append) and can inject persona noise. The design comment (`:94-96`) records that cross-lab critics flagged this and the resolution was the hybrid (principle leads, name calibrates, guardrail fences theatrics). The recommendation (see README systemic findings) is to lean further into specificity: the three principles are already well-specified enough that the names could be dropped entirely with little signal loss and a cleaner guardrail-free block. That is a refinement, not a correctness bug.
- **Double exposure, worth it?** For THIS block, yes. It is the one behavioral default the proxy most wants to win, and it must reach BOTH the main agent (system-prompt salience) AND descendants (CLAUDE.md, since subagents do not get `--append-system-prompt`). The main agent seeing it twice (system turn + CLAUDE.md top) is a mild redundancy cost, but the two surfaces serve different audiences and the block is short (1137 bytes), so the overlap is cheap. This is the correct block to double-expose; see the README for why not every block is.

## Findings + verdict

**Finding 1 (framing, the headline call):** The named-celebrity "bar to clear" framing (Jobs and Ive / Gates / Bezos) is a soft fail against Anthropic's specificity guidance, even in its mitigated hybrid form, because the names occupy the highest-salience slot. It is already well-mitigated (principle-led, name as calibration, explicit no-impersonation guardrail, regression-pinned exact-case in `tests/isolated/claude-md-injection.test.ts`). **Recommendation (specificity compensation)**: since each principle is already stated functionally and concretely, drop the parenthetical names and let the specified behavior carry the signal, e.g. "radical simplicity and relentless focus on the user's real experience for design; whole-systems first-principles thinking that anticipates scale and the long arc for architecture; customer obsession that works backwards from the outcome for product." This removes the high-variance vector and the need for the theatrics guardrail. Severity: Suggestion (the current form is defensible and tested; this is an optimization toward the specificity bar, not a fix for a defect).

**Finding 2 (positive, keep):** The orchestrate paragraph is a model of good injected-default writing, positive, explicitly scoped, overridable, with the failure-mode carve-out (do last-mile work directly) built in. No change.

**Finding 3 (positive, keep):** The override header and the `not a persona` guardrail correctly handle the two literalness hazards (blanket delegation, persona impersonation). Keep.

**Verdict**: Structurally strong, honestly framed as an overridable default, no enforcement overclaim, no aggressive-imperative overtrigger. The single soft fail is the named-persona calibration; it is well-mitigated and tested, and the recommended refinement is to compensate with specificity by dropping the names. Double exposure is justified for this block.
